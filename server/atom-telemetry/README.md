# Atom Telemetry

A small, self-hosted service for anonymous Atom VPN installation and active-user counts.

## Collected data

The Android client sends only:
- a random per-install UUID generated by the app;
- event type: `install` or `active`;
- Atom app version;
- event timestamp.

The client does not add a phone number, account identifier, hardware identifier, IP address, destination, DNS query, or VPN traffic content. The API does not persist request IP addresses. Run the service behind a reverse proxy configured not to retain access IP logs and apply request rate limits there.

Statistics are opt-in in the Android app. Users can disable future reporting at any time. Disabling clears unsent events on the device; it does not erase previously received aggregate records from the server.

## Run with Docker

Create a long random admin token, then run:

```sh
docker build -t atom-telemetry server/atom-telemetry
docker run -d --name atom-telemetry \
  --restart unless-stopped \
  -p 127.0.0.1:8080:8080 \
  -v atom-telemetry-data:/data \
  -e ATOM_TELEMETRY_ADMIN_TOKEN='YOUR_LONG_RANDOM_SECRET' \
  atom-telemetry
```

Put HTTPS in front of port 8080 using a reverse proxy. Do not expose the admin token to the Android app.

Health check: `GET /health`

Public ingest: `POST /v1/events/batch`

Admin statistics: `GET /v1/admin/stats` with header `X-Admin-Token: YOUR_LONG_RANDOM_SECRET`.

## Android configuration

Set the Gradle property `ATOM_TELEMETRY_URL` to the HTTPS base URL of this service when building the release, for example:

```properties
ATOM_TELEMETRY_URL=https://telemetry.example.com
```

Do not put the admin token in the Android app. The ingest endpoint accepts only the small, schema-validated anonymous event payloads; protect it with reverse-proxy rate limiting.

## Metric definitions

- Total installations: distinct installation UUIDs that sent an `install` event.
- DAU: distinct installation UUIDs with an activity event on the current UTC date.
- MAU: distinct installation UUIDs active in the last 30 UTC calendar days.
- New installs today: install events first received on the current UTC date.

Counts begin only after a user enables anonymous statistics and the app sends its first event. Existing installs cannot be reconstructed retroactively. Clearing app data creates a new random installation ID and may count as another installation.
